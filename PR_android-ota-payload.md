Title: feat(artifacts): inventory Android OTA update payloads offline

## Summary

`inspect-artifact` and `extract-artifact` had no reader for Android A/B
OTA `payload.bin` (update_engine, magic `CrAU`). An analyst could not
ask which partitions a payload writes, what sizes and hashes the
manifest declares, whether it is full or delta, or which install
operations are present.

No existing issue tracks this. This change adds a read-only CrAU v2
inspector on the shared artifact inventory/extract path.

## Problem and expected behavior

A local `payload.bin` (or a zip member of that name) should classify by
the `CrAU` magic, independent of file name. Version 2 inventories the
header and `DeltaArchiveManifest`. A readable major version other than 2
is a typed unsupported-version refusal. Signatures are counted, not
verified. REPLACE, ZERO and REPLACE_ZSTD partitions can be reconstructed
against `new_partition_info` hash; other operation types stay inventoried
and refuse content reads. A truncated blob keeps a complete manifest
inventory and records the truncation.

## Change and scope

Domain parser `src/domain/firmware/androidOtaPayload.ts` owns the 24-byte
v2 header, protobuf decode of the fields this reader reports (field
numbers cited from AOSP `system/update_engine/update_metadata.proto`),
capacity ceilings, recognition, and bounded reconstruction.
`AndroidOtaPayloadArtifactReader` inventories partitions from the
manifest and reconstructs extractable images on `open()`. Recognition
sits in the shared `ARTIFACT_FORMAT_RECOGNIZERS` table so classification
and `open_binary` share one verdict. Nested zip `payload.bin` members
classify by magic; zip inventory does not recurse into partitions.

This is a local, read-only artifact reader. It does not execute a target,
inject instrumentation, mutate bytes, or recover protected code.

## Contract and boundary impact

- Semantic owner and earliest changed stage: `androidOtaPayload.ts` owns
  CrAU/manifest facts; `AndroidOtaPayloadArtifactReader` owns inventory
  and reconstruction. Downstream consumers use those parsed facts and
  the existing inspect/extract contracts.
- Contribution scope fit and linked maintainer decision: not applicable.
  Read-only inventory of a caller-selected local file; no execution,
  injection, mutation, or protection recovery.
- CLI and MCP/tool-catalog contract: existing `inspect-artifact` /
  `inspect_artifact`, `extract-artifact` / `extract_artifact`, and
  `open_binary`. New format id `android-ota-payload` on those results.
- Provider, bridge, target-format, or platform compatibility: CrAU v2
  only. Version 1 is refused. Nested zip members classify by magic.
- Evidence, artifact, provenance, or reconstruction contract: root
  format metadata carries header, manifest, signature counts with
  `signatures_verified: false`, and per-partition operation counts.
  Reconstructed images are not file ranges (`byteOffset: null`).
  Non-extractable members use `hash_status: unavailable`.
- Target selection, authority, upstream behavior, and cleanup details (if applicable):
  caller-selected local path; reader close joins member streams.
- Generated metadata (`docs/public/product-catalog.json`), package, or installation impact (CI generates and validates ignored catalogs and `skills/`; edit authored instructions in `.agents/skills/reverse-engineer-anything/` and never commit build outputs):
  authored skill text in `native-and-artifacts.md`; catalogs regenerated by CI.

  `bluejay-ota_update-2026111300.zip` `payload.bin` prefix (HTTP range
  `bytes=4282-132551`, SHA-256
  `549511763adf903ed426d46621c2ac1ee88dda502567d26b9db3521ca2db190f`)

- User-visible CLI/MCP output (if applicable): see validation commands
  below and the captured log on `demo/android-ota-payload`.
- Remaining proof gaps: payload and metadata signatures are not verified;
  delta operations are not applied; compressed operation types other than
  REPLACE_ZSTD are unsupported; no real-world corpus beyond the GrapheneOS
  header+manifest prefix and synthesized fixtures.

Applicable boundary regressions: truncated/malformed input, capacity
ceilings, integrity (declared digest mismatch), recognition refusal for
unsupported version. Lifecycle: preparation recovery and cancellation
during reconstruct; reconstructed members are not positional file ranges,
so artifact-reader lifecycle cases that require `byteOffset` do not apply.

## Compatibility, safety, and release

- Breaking changes or migration steps: none. New format id only for CrAU v2 bytes; other formats keep their routing.
- Real Hopper/Ghidra, browser, or OS coverage: not applicable; this path is the portable artifact reader.
- Package or release metadata impact: none beyond the new format id and docs.
- Security, privacy, process, or containment review: local read of a caller-selected file; reconstruction bounded at 32 MiB per partition; signatures are not treated as verified.
